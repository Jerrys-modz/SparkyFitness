# React Query And Local State: details

Longer notes for the "React Query And Local State" section of [`SparkyFitnessMobile/AGENTS.md`](../AGENTS.md). Each one has a one-line link there.

## App-local toggles (appPreferencesStore)

- App-local toggles live in `stores/appPreferencesStore.ts` (Zustand `persist`, single AsyncStorage key `@SparkyFitness/app-preferences`): haptics, sounds, notifications, hydration/fasting card visibility, Ask Sparky and progress photos card visibility, the Liquid Glass tab bar opt-in, the guided check-in opt-in (`guidedCheckInEnabled`, edited in `DiarySettingsScreen`, adds the AddSheet's Check-In row), the active-workout metric column, the default rest period (`defaultRestSec`, edited in `WorkoutSettingsScreen`), mood check-in reminders (`checkinRemindersEnabled`, `checkinReminderTimes`, edited in `NotificationSettingsScreen` and offered once after the first check-in), hydration reminders (`waterReminderEnabled`, `waterReminderIntervalHours`, `waterReminderWindowStart` / `waterReminderWindowEnd`, edited in `NotificationSettingsScreen`), the Health Trends layout (`healthTrendOrder` + `hiddenHealthTrends`, plus `healthTrendsLayout` `pager`|`tiles`, up to `MAX_HEALTH_TREND_TILES` chosen `healthTrendTiles` and a per-graph window `healthTrendRanges`, `healthTrendsShowReportsLink` and `healthTrendsShowRangeControl` to hide those two controls on the card, edited in `HealthTrendsSettingsScreen` and the Dashboard's range control; the Dashboard loads each window with its own `useHealthTrends` call, `HealthTrendTiles` draws the tiles from `utils/healthTrendTiles.ts`, and `HealthTrendChart` is the one place a graph key maps to its chart), the Dashboard's Activity Rings card (`activityRingsCardVisible`, `activityRingStyle` `apple`|`google`|`custom`, `activityRingCustom`, `standGoalHours`, `activityRingsCompact`, edited in `ActivityRingsSettingsScreen`; the Stand ring is iOS only: `useStandHours` reads Apple Health's stand hours on the device through `services/standHours.ios.ts` (`HKCategoryTypeIdentifierAppleStandHour`, never uploaded; the Android stub reports nothing) and the ring is dropped where `STAND_HOURS_SUPPORTED` is false; Active points are summed client-side from each workout's stored time in heart rate zones by `utils/activityRings.ts`) and At a Glance strip (card key `pinnedMetrics`: `pinnedMetricsCardVisible`, `pinnedAuto` (default on: `GLANCE_AUTO_CANDIDATES`, skipping what another visible card shows and anything with no data, `pickGlanceMetrics` in `utils/pinnedMetrics.ts`), else up to `MAX_PINNED_METRICS` (6) `pinnedMetrics` such as `ring:move`, `goal:protein` or `trend:weight`, edited in `PinnedMetricsSettingsScreen`; both cards are opt-in, hidden by default), the Dashboard tabs (`dashboardTabsEnabled`, on by default, and the last open `dashboardTab`, read through `resolveDashboardTab` so a tab a later build drops falls back to Summary; edited in `DashboardSettingsScreen` and by the tab control), the Reports layout (`reportOrder`, `hiddenReports`, `reportDefaultRange`, `hiddenReportSections`, `reportNutrientOrder`, `shownReportNutrients`, edited in `ReportsSettingsScreen`), the Compare report's recent questions (`compareRecentQuestions`, newest first, max 5, written by `CompareReportScreen` and read through `knownCompareQuestions`, which drops any a later build no longer knows), and the Apple Watch layout (`watchPageOrder` + `hiddenWatchPages`, the Goals page's `watchNutrientOrder` + `shownWatchNutrients`, and `watchSetInputStyle`, all edited in `WatchSettingsScreen`). The Health Trends pair is written through the single `setHealthTrendLayout(order, hiddenKeys)` setter rather than one per field, because one drag changes order and visibility together; a saved order is reconciled against `constants/healthTrends.ts` by `resolveHealthTrendOrder`, so registering a new graph needs no `STORE_VERSION` bump. Consume via selectors (`useAppPreferencesStore((s) => s.hapticsEnabled)`) plus generated setters; non-React code reads current values through helpers like `getDefaultRestSec()`. A legacy-aware storage adapter migrates the old per-key `@HealthConnect:*` values once. These preferences never sync to the server.
